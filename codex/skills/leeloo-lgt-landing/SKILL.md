# Leeloo LGT Landing Builder

Ти збираєш лендинг для клієнта Leeloo.ai за форматом бойових LGT самої Leeloo. Формат
працює, бо він зроблений під людину, яка прийшла з реклами на телефоні: один «екран
застосунку» на 560px, УТП з одним градієнтним акцентом, живе медіа, цифри-докази,
логотипи, і конкретний список «що отримаю за підписку» — одразу над формою Leeloo.

Твоя робота — зберегти цей формат і **повністю замінити наповнення** на клієнтське:
його бренд, кольори, лого, креативи (відео/фото), його цифри, його клієнтів у логотипах,
його відгуки, його оффер. Нічого від Leeloo у контенті лишатися не має.

## Робочий процес

```
1. БРИФ (блоками)  →  2. КАРТА ЕКРАНІВ + ТЗ  →  3. ПІДТВЕРДЖЕННЯ  →  4. ЗБІРКА  →  5. ПЕРЕВІРКА + ВИДАЧА
```

Не пиши код до кроку 4. Лендинг без брифу — це лендинг Leeloo з чужим лого, а не лендинг
клієнта. Якщо користувач уже дав частину відповідей (файли, текст оффера, посилання на
сайт) — не перепитуй, зафіксуй і йди далі.

### Крок 1 — Бриф

Веди блоками, по одному за раз. Кожен блок — 3–5 питань, чекай відповіді.

**Блок A — Бізнес і оффер**
1. Що продаємо і кому (ніша, сегмент, гео)? Є сайт/Instagram — дай посилання, подивлюсь стиль.
2. Який **лід-магніт / перший крок** отримує людина за підписку в месенджері? (консультація,
   розрахунок, PDF, пробне заняття, знижка). Це стане списком «Залишайте заявку, щоб отримати».
3. Головний результат для клієнта + термін + гарантія, якщо є (це основа УТП).
4. 2–3 заперечення, які треба зняти (дорого / довго / складно / не спрацює) — стануть чіпами.
5. Мова лендингу.

**Блок B — Бренд і кольорова гама** (читай `references/palettes.md`)
6. Лого: SVG (найкраще) або PNG з прозорим фоном. Файл або URL.
7. Кольорова гама — питай трьома рівнями і зупиняйся на першому з відповіддю:
   є брендбук → hex-коди; є лого/сайт → витягни 2 кольори і покажи; нічого → покажи
   каталог із 12 готових гам (`palettes.md §2`), запропонуй одну під нішу, дай обрати номер.
8. Тема: **dark** (tech, AI, фінанси, преміум, темні креативи) чи **light** (медицина, освіта,
   діти, бʼюті, e-commerce, кольорове лого)? Запропонуй одну з поясненням, дай вибрати.
9. Покажи картку гами (акцент / другий / фон з hex і що чим фарбується) і дочекайся «ок» —
   у ТЗ гама йде першим рядком.

**Блок C — Докази**
10. Цифри: рік заснування, кількість клієнтів/проєктів, міст/країн, рейтинг, оборот — що є.
11. Логотипи клієнтів / партнерів / ЗМІ / маркетплейсів — мінімум 6 файлів PNG/SVG
    (прозорий фон). Немає — блок логотипів пропускаємо, докази лишаємо цифрами.
12. Відгуки: 2–3, кожен з імʼям, роллю/містом, конкретним результатом і, бажано, фото.
    Скріншоти переписок теж підходять (окремим блоком-картинкою).

**Блок D — Медіа**
13. Є відео-демо / креатив 15–60 с без звуку (mp4 + постер, за URL)? Або фото-креатив?
    Або довге відео на YouTube (VSL, розбір) — тоді робимо окрему частину з фасадом.
14. Медіа без URL → поясни: файли треба захостити (медіатека Leeloo → блок «Зображення» →
    скопіювати URL; Google Drive `drive.google.com/uc?id=…`; Imgur; CDN сайту). Дрібні
    (лого, логотипи, аватарки ≤ 15 KB) можна дати файлами — я інлайню їх у код.

Принцип: збирай **факти**, не формулювання. Тексти УТП, чіпів і списку пишеш ти — за
формулами з `components.md` (розділи 3, 6, 7, 9), мовою клієнта і без жаргону Leeloo.

### Крок 2 — Карта екранів і ТЗ

Запропонуй розкладку сторінки. Базова, з бойових LGT:

```
Частина 1 (HTML)  бренд-бар · tag · УТП · медіа + смужка месенджерів · vcap · чіпси · соцдоказ · логотипи · getlist
Форма (Leeloo)    нативна форма підписки — НЕ верстаємо
Частина 2 (HTML)  чекліст «Що ви отримуєте» (4–6 пунктів)  [+ відгуки]
Частина 3 (HTML)  відео-фасад + місток                     [якщо є довге відео]
Форма (Leeloo)    дубль CTA внизу                          [опційно]
```

Скорочуй під клієнта: немає довгого відео — без частини 3; немає логотипів — без `.logos`;
відгуки є, чеклісту немає — частина 2 = відгуки. Не додавай блоки, яких немає в
`components.md`, без явної потреби: формат навмисно стислий.

ТЗ покажи компактно: тема + акцентні кольори, текст УТП (з позначенням градієнтного
фрагмента), tag, чіпи, vcap-ланцюжок, речення соцдоказу, пункти getlist, пункти чеклісту,
відгуки, які медіа куди. Запитай: «Все вірно? Збираю, чи є правки?»

### Крок 3 — Підтвердження

Правки → оновлюєш ТЗ → показуєш знову. «Ок» → крок 4.

### Крок 4 — Збірка

1. Прочитай `references/part-templates.md` і візьми скелет A (dark) або A+B (light) для
   частини 1, скелет C + потрібний контент (D/E/F) для кожної наступної частини.
2. Перефарбуй токени під підтверджену гаму за `palettes.md §3` (з двох кольорів у повний
   набір, перерахунок rgba-дублікатів акценту: тіні крапки, glow-плями, тінь номерів) і
   `design-system.md §4`.
3. Заповни тексти з ТЗ. Ассети — плейсхолдерами: `{{asset:logo.svg|fill=#FFF}}`,
   `{{msgr-bar}}`, `{{logos:a.png,b.png,…|mono}}`, фото/відео — URL напряму.
4. Збережи вихідники як `<client>-part1.src.html`, `<client>-part2.src.html`…, файли клієнта
   поклади в папку (напр. `./assets-<client>/`).
5. Збери кожну частину (на Windows запускай з PowerShell і абсолютними шляхами — Git Bash
   падає на довгих шляхах з «cwd too long»):
   ```bash
   python scripts/build_lgt.py client-part1.src.html --part 1 --asset-dir ./assets-client -o client-part1.html
   python scripts/build_lgt.py client-part2.src.html --part 2 --prefix p2- --asset-dir ./assets-client -o client-part2.html
   ```
   Скрипт інлайнить ассети і валить збірку, якщо: у частині 2+ є `:root/html/body` або
   неспрефіксовані класи; у частині 1 нема хаку `--host-gap`; є `<form>`, `localStorage`,
   незбалансовані теги, залишені `{{…}}`. Виправляй і збирай знову, поки не «✔ перевірка пройдена».
6. Відкрий зібраний файл у браузері (шириною 390px) і глянь: чи не обрізаний курсив у
   заголовку, чи логотипи рівні, чи не переповнює текст картку. Довгі УТП (> 2 рядків
   градієнта) скорочуй — це не сайт.

### Крок 5 — Видача

Віддай **окремі файли по частинах** (не один склеєний — у Leeloo це різні блоки), а після
них — інструкцію зі вставки з `host-integration.md` (порядок: HTML 1 → Форма → HTML 2 →
HTML 3). Скажи, що перевіряти треба на публічному URL LGT з телефона, і що `--host-gap`
підправиш за скріном, якщо зверху щілина.

Якщо клієнт хоче форму всередині дизайну / стилізовану під бренд / у кількох місцях —
скажи, що це робить скіл `leeloo-design-fit` поверх частини 1, і додай у `:root` змінні
`--tg-1/--tg-2/--wa-1/--wa-2/--ease` (див. `host-integration.md`, правило 3).

## Принципи, які не обговорюються

- **Формат Leeloo, контент клієнта.** Жодного «Leeloo», «туннель продажів», «8 500 бізнесів»
  у текстах, жодного лого Leeloo. Смужка месенджерів — можна: вона про канал спілкування.
- **Одна картка, 560px, мобільний first.** Не роби секції на всю ширину, сітки з трьох
  колонок, «сайтові» хедери з меню.
- **Частина 1 — господар, частини 2+ — гості** з префіксами. Скрипт перевіряє, ти —
  не обходиш перевірку `--no-check`.
- **Форму не верстаємо.** Немає `<form>`, `<input>`, своїх кнопок «Надіслати». CTA лендингу —
  список getlist + нативна форма Leeloo під ним.
- **Медіа за URL, дрібниці інлайном.** Частина ≤ 150 KB.
- **Тексти пишеш ти** за формулами компонентів: УТП = результат за термін + механізм у
  градієнті + масштаб/гарантія тихо; чіпи = зняті заперечення; subproof = 1 речення, 2–3
  числа; getlist = 2–3 пункти, перший — найцінніший і безкоштовний, у `[дужках]` — «зазвичай $X».
- **Не вигадуй цифри й відгуки.** Немає даних — пропусти блок або постав `[ЦИФРА]` і скажи
  клієнту, що заповнити.

## Заборонено

- ❌ Писати код до підтвердження ТЗ
- ❌ Лишати в текстах контент Leeloo (крім смужки месенджерів)
- ❌ `:root`, `html`, `body`, загальні селектори або класи без префікса у частинах 2+
- ❌ Свої форми, інпути, `fetch`, зовнішні JS-бібліотеки, `localStorage`
- ❌ Інлайнити відео чи фото > 150 KB у base64
- ❌ Склеювати частини в один файл або віддавати без інструкції зі вставки
